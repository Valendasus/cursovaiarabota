# Учёт партий продуктов в сети магазинов у дома

Учебный прототип выполняет три операции. Он распределяет продажу по годным партиям в порядке FEFO, выводит партии с истёкшим и приближающимся сроком годности и рассчитывает рекомендацию для пополнения магазина. Входные данные демонстрационные.

## Запуск

Выполняйте команды из папки «Прототип». Нужны Python 3.9+ со стандартным модулем sqlite3 и JDK 11+.

```sh
python3 inventory.py
python3 inventory.py --db demo.sqlite3
python3 -m unittest -v
javac -encoding UTF-8 -Xlint:all java/InventoryDemo.java java/InventoryTest.java
java -cp java InventoryDemo
java -cp java InventoryTest
```

Первый запуск Python использует базу в памяти. Параметр `--db` позволяет создать новый файл для просмотра таблиц. Java выполняет тот же демонстрационный сценарий в памяти.

## Правила демонстрации

- `expires_on` обозначает первую дату, с которой партию блокируют для продажи. Партию можно использовать, когда её дата окончания годности позже даты операции.
- Цены хранятся в копейках и фиксируются при продаже. Источник цены — ассортимент конкретной точки.
- В рекомендации учитываются только подтверждённые поступления. Рекомендация отображается для сотрудника, который принимает решение о заявке.
- FEFO применяется к подготовленным для отпуска партиям. Если реализуют самообслуживание, идентификатор партии фактически выбранного товара получают отдельно.

## Сервер на Spring Boot

Для запуска без Docker нужны JDK 21 и Maven. Выполняйте команды из папки «Прототип».

```sh
mvn verify
java -jar target/store-inventory.jar
```

Сервис использует общие файлы `schema.sql` и `demo.sql`. При первом запуске создаётся `inventory.sqlite3`. Чтобы открыть существующую базу с этой схемой, задайте `INVENTORY_DATABASE` с её путём. Установка `INVENTORY_SEED_DEMO=false` создаёт новую базу с пустыми таблицами.

| Метод и путь | Параметры |
| --- | --- |
| `POST /api/stores/{storeId}/sales` | JSON с датой `date` и корзиной `items`, где ключ — SKU, значение — количество |
| `GET /api/stores/{storeId}/expiry-alerts` | Дата `date` и горизонт `days` (по умолчанию 2) |
| `GET /api/stores/{storeId}/replenishment` | Дата `date` |
| `GET /actuator/health` | Проверка доступности сервиса и базы |

Даты передаются в формате `YYYY-MM-DD`. Продажа возвращает `201 Created`, идентификатор, итог в копейках и распределение по партиям. Неверный запрос возвращает `400`, неизвестный магазин — `404`, недостающий товар или SKU вне ассортимента — `409`.
